# RMUC 2026 功能区与相邻移动

## 坐标和输出约定

- 场地固定为 `28m × 15m`，红方侧 `x=0`、蓝方侧 `x=28`。
- `worldstate.robots[*].zone` 现在直接输出功能区名称；`legacy_zone` 保留旧 6×3 网格标签。
- 预测输出中的每个单位包含：`from_zone`、`to_zone`、`movement.description`。格式固定为：

```text
步兵3：红上公路 → 中央北隧道
```

如果连续坐标模型直接跳到了不可达区域，输出同时保留 `raw_to_zone`，并把 `to_zone` 投影到满足通行图、路径长度和 `speed × horizon` 的合法路线；10 秒最多一条边，长时可沿多条边展开，标记 `projection_applied=true`。

## 功能区

| 功能区 | 作用 |
|---|---|
| 红/蓝基地 | 基地 footprint，不能作为普通自由通道 |
| 红/蓝上装配区、下装配区 | 出生/装配/起降附近区域 |
| 红/蓝前哨区 | 前哨站及其交互 footprint |
| 红/蓝上公路、下公路、中路 | 地面机器人主要候选路线 |
| 红/蓝梯形高地区 | 条件通行的抬升结构 |
| 中央北隧道、中央南隧道 | 连接公路与中央高地的入口 |
| 中央高地 | 条件通行的核心抬升区 |
| 场地开放区 | 图纸未细分但在场地内部的开放地面 |
| 场地未知区 | 场外、边缘或尚未由 CAD/现场确认的位置 |

## 官方规则中的交互模块

规则手册 V1.3.0 的场地图把补给区、能量机关区、停机坪/飞行区、前哨站、基地、道路、隧道和中央高地作为独立模块。当前规划图将这些模块显式命名，避免把所有未细分地面都标成“未知区”：

- 红/蓝补给区：规则图中的资源站和补给区点；补给区内放置能量单元，工程机器人在这里取得、携带并交付能量单元。
- 红/蓝能量机关区：能量机关及其可交互 footprint；预测可以把“攻击能量机关”作为攻击目标类型单独记录。
- 红/蓝停机坪：停机坪和飞行相关交互点；空中机器人状态同时输出飞行中、停机坪和落地/未知。
- 前哨区、基地区：保留结构物状态（active/damaged/destroyed/unknown）以及守卫/攻击交互状态。

这些是规则驱动的规划级功能区。STEP/CAD 边界、机器人包络、坡度和动态占用仍需要现场标定；在没有标定前，系统会保留 `raw_predicted_zone`，并把动作目标投影到速度和时距允许的合法路线。

## 兵种特化状态

预测的空间字段和兵种状态字段并列输出。状态字段不会把雷达看不到的细节硬填成真值，缺字段时统一为 `unknown`，并保留证据来源。

| 兵种/对象 | 当前状态 | 预测状态 |
|---|---|---|
| 英雄、步兵 3/4 | 是否攻击、是否可能攻击、正在/可能攻击的目标、是否攻击能量机关 | `attack_status_probabilities`、目标对象和攻击能量机关概率 |
| 哨兵 | 上述攻击字段，加上守基地/守前哨/巡逻 | `defense_status_probabilities` 和防守目标 |
| 工程 | 是否持有能量单元、是否在补给区兑换、去资源区还是回补给区 | `resource_status_probabilities`、`resource_phase_probabilities`、`has_energy_unit_probability` 和 `from_zone → to_zone` |
| 空中 | 飞行中/停机坪/落地，加上可见目标攻击状态 | 飞行状态概率和攻击状态概率 |
| 基地、前哨站、能量机关、能量单元 | active/damaged/destroyed/unknown、交互对象类型 | 结构/交互状态持续性先验 |

工程的“矿区”在规则数据中对应本方补给区/资源站点；输出仍使用正式功能区名，例如：

```json
{
  "resource_phase": "returning_to_exchange",
  "resource_direction": "to_supply_area",
  "resource_route": {
    "from_zone": "红中路",
    "to_zone": "红补给区",
    "description": "工程：红中路 → 红补给区"
  }
}
```

攻击目标和工程持矿只有在当前观测中存在相应传感器字段时才会被确认；对手侧通常只有类型、位置、血量、金币和雷达高亮等可见字段，因此“正在攻击”和“持有能量单元”在缺少直接字段时保持未知，几何上可达的目标只标为 `possible_*` 推断。

## 相邻图和兵种限制

- 英雄、步兵 3/4：可沿图中相邻边移动，允许进入中央隧道和中央高地；敌方基地/装配区不作为普通穿行目标。
- 工程：默认只在己方前缀功能区内移动，不跨越中心；这是项目战术先验，不是物理墙。
- 哨兵：默认只在己方基地侧的前哨、公路和梯形高地区活动，不进入中央高地、敌方区或装配/基地 footprint。
- 空中：使用相邻功能区作为报告轨迹，不能出现“从一个区域瞬移到任意远区”；飞行安全和空域限制另行检查。
- 所有兵种都允许“留在当前功能区”，但 `场地未知区` 默认不能作为合法移动目标。

详细边表和规则实现见 `worldstate/functional_zone.py`。这是规划级功能区图，最终路径仍需叠加机器人包络、坡度、动态占用和现场标定。


## 全局状态字段（运行时）

`derive_global_analysis` 现在额外提供：

- `control_posture`、`zone_control`：区域控制与争夺关系；
- `risk_register`：基地、前哨、入侵单位和脆弱单位风险；
- `special_state_summary`：攻击、哨兵防守和工程资源阶段摘要；
- `economy`：双方金币和工程状态；
- `recommendations`、`decision_gates`：带触发条件和回退动作的建议。
- 预测旁路的 `decision_summary`、`force_balance`、`engagement`、`objective_status`、`mobility` 和 `forecast_scope`：分别服务于决策承诺、兵力准备度、交战目标、建筑目标、合法移动和时间窗粒度。

自然语言旁路只叙述这些字段之间的因果关系，不把原始坐标表和概率表重复写进段落。
