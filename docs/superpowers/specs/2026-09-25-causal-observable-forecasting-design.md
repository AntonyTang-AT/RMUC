# RMUC M2 因果可观测的多时距态势预测设计

日期：2026-09-25  
状态：待项目负责人审阅  
范围：M2 状态标准、概率预测目标、按时间成熟的评估与校准接口

## 1. 目标与已确认约束

系统从历史比赛中学习并预测比赛态势，在部署时严格限制为车载传感器和雷达实际可见的信息。输出覆盖三个时间尺度：我方约 10 秒的短期态势与建议、全局约 30–60 秒的中期态势、敌方约 1–2 分钟的位置区域和攻防趋势。每个离散判断可以输出多个候选及概率；位置等连续量使用概率分布或预测区间。

比赛回放的全局状态只用于产生未来目标值和事后核验，不得作为部署模型的当前输入。每条预测必须有发出时刻、目标时刻和输入快照；只有比赛时间推进到目标时刻并获得对应实际状态后才评分。训练、验证和盲测按正式比赛顺序分组，禁止同一局或同一对阵跨分区造成泄漏。

人工标注当前不作为前置条件。自动规则标签可以保留为弱标签或比较基线，不能称为人工金标准。

## 2. 现状与已发现风险

- SQLite `timeseries` 同时记录红蓝双方实体，原始数据库是全局回放；当前运行策略以红方为己方计算，属于单边决策视角。
- `data/features.py` 当前按 3 秒构造决策点，并使用 `<= t` 最近记录对齐机器人；但 `_closest` 在没有任何 `<= t` 的记录时返回该实体第一条记录。抽查局在第 1 秒才有首条状态，当前 t=0 决策点因而会读入 t=1 状态。该行为违反因果输入要求，必须修复。
- 现有 `WorldState` 对原始状态做了归一化和舍入，并丢弃部分原始字段。它可继续作为现有规则模块的输入，但不应作为唯一的状态真源。
- 现有 lookahead 标签由未来窗口的机器人位置和建筑血量变化推导，标签定义取决于规则、窗口和阈值。它是弱监督目标，不证明推荐决策的因果收益。
- 历史 SQLite 有全局敌方轨迹，但没有明确的车载相机视野、雷达探测时间、遮挡、测距误差和轨迹失效记录。只有全局真值不足以构造真实部署时可见的敌方输入。

## 3. 设计原则

1. **因果截断**：发出时刻为 `t` 的所有输入，只能依赖观测时间不晚于 `t` 的数据。插值、滤波和趋势特征也必须单向使用过去数据。
2. **观测与真值分层**：同一比赛可有 `observable_input(t)` 和 `global_truth(t)` 两个视图。模型只读前者，未来目标和评分只读后者。
3. **显式未知**：未观测、信号过期、实体未出场、实体已确认失效是不同状态。不得用未来坐标填缺失值，也不得把未观测解释成不存在。
4. **阵营对称**：状态数据按红/蓝原始阵营保存；对模型建立 `self/opponent` 映射，并保证交换红蓝后结构一致。
5. **预测与行动分离**：预测“会发生什么”与推荐“应采取什么行动”是不同任务。回放未来可监督前者；后者若要评估收益，需要行动日志、可靠仿真或反事实设计。
6. **概率可核验**：每个概率输出绑定明确定义的互斥/可并事件、目标时刻与标签构造版本，并使用适当评分规则评估。

## 4. 推荐架构

采用一个共享的因果状态层，后接按目标和时距区分的预测头。保留规则系统用于安全约束和基线；Jev 可作为产生类型化概率判断的候选后端，但不能绕过可观测输入、输出校验、预测账本和标准评分。

```text
传感器 / 雷达观测 ──> 可观测性适配器 ──> 因果状态快照(t)
                                           ├─ 10s 我方短期态势 / 候选建议
                                           ├─ 30–60s 全局态势分布
                                           └─ 60–120s 敌方区域与攻防分布

全局回放真值 ──> 未来目标构造 ──> 预测成熟账本 ──> 概率评分 / 校准 / 版本化更新
```

共享状态编码、分时距输出头比一个混合所有目标的单一输出更容易定义目标、定位误差来源和分别校准。每个头应显式声明其预测的实体、状态维度、地平线及可用观测范围。

## 5. 统一状态与时间标准

### 5.1 规范实体状态

建立不可有损的规范状态记录，至少包含：

```text
game_id, match_id, t_game, entity_id, team, entity_type,
position(x,y,z), orientation, hp, hp_max, power, heat, ammo,
presence_state, observability_state, observed_at,
source, measurement_confidence
```

原始传感值保持原精度。归一化坐标、区域、速度、攻防特征作为带版本的派生字段生成，不覆盖原始值。派生状态需要记录算法版本和输入字段。

### 5.2 时间对齐

- 原始数据库以其实际秒级记录作为历史真值时间轴。若在线控制仍以 3 秒为一次决策，应从首次有效观测开始按 `t0 + k*3s` 取样；不得在没有观测时伪造 `t=0` 状态。
- 对每个实体使用向后 as-of 对齐，只选择 `observed_at <= t` 的最新记录，并保存观测年龄。
- 观测年龄超过实体/传感器类型的有效期时，置为 stale/unknown；在阈值内可前向保持最新观测，但必须携带年龄和置信度。
- 多传感器融合仅使用接收时刻不晚于 `t` 的测量；离线乱序数据按“可用时间”而非未来修订时间回放。
- 速度、趋势窗口只使用 `[t-W,t]` 内的历史观测。未来窗口只用于目标标签。

### 5.3 部署可观测输入契约

可观测性适配器接受车载状态、相机/雷达检测或跟踪结果，输出统一实体轨迹及其置信度、观测时间和失效状态。敌方位置只允许输入当时雷达或视觉真正探测到的估计值；未探测敌方可以输出基于历史轨迹的信念分布，不能读取回放真值坐标。

训练数据构造必须获得传感器日志、正式的可见性标记，或经过校验的传感器可见性重放器（视场、距离、遮挡、探测概率、延迟和测量噪声）。当前数据库不含这些完整字段，因此没有这类信息的训练集只能标成“全局回放 oracle 实验”，不能用于证明部署效果。首个可部署预测基准的前置门槛是定义并验证上述可见性来源。

## 6. 预测目标与标签

每条样本以发出时刻 `t` 为锚点，先生成可观测输入历史 `X(<=t)`，再从全局真值构造未来目标 `Y(t+h)`。时间地平线首版固定为：

| 任务 | 地平线 | 首版目标 |
|---|---:|---|
| 我方短期态势 | 10 秒 | 双方相对区域变化、己方关键实体/建筑状态变化、威胁事件概率；另行输出候选行动建议及概率/排序 |
| 全局中期态势 | 30 秒、60 秒 | 区域控制、双方阵型/推进深度、关键实体生存/建筑状态、攻防态势概率 |
| 敌方宏观预测 | 60 秒、120 秒 | 敌方各实体/编队的位置区域概率分布、推进/防守/撤退倾向、关键目标威胁概率 |

区域体系须使用固定地图坐标和冻结的区域定义，不能按每局动态 min/max 归一化，否则同一区域会随比赛范围变化。连续位置预测应包含概率分布或分位数区间；分类态势输出完整概率向量，而非只输出 argmax。

对比赛剩余时长不足 `h` 的锚点标为 censored，不生成目标、不计该时距分数。目标标签直接描述未来观测到的实际状态/事件。规则推导的“应当进攻/防守”等只作为独立弱标签列，不覆盖实际目标。

短期行动推荐需要有独立策略目标，例如在候选动作下预测的己方生存、基地/前哨站血量变化和资源收益。历史回放中实际发生的状态变化不能自动视为“最佳动作标签”。首版可输出可解释的候选建议，但必须把“态势预测质量”和“行动收益”分别报告；后者在缺少动作日志或可信反事实评估时标记为未验证。

## 7. 概率输出与预测账本

预测统一记录以下字段：

```text
prediction_id, game_id, issued_at, valid_at, horizon,
task, entity_or_region, target_schema_version,
probability_distribution / quantiles,
input_snapshot_hash, visibility_summary,
model_version, calibration_version
```

每到 `valid_at`，评估器只读取该时刻已成熟的真值，将其与当初存档预测配对并评分。晚到数据、目标缺失和实体不可观测分别记录原因，不静默删除。

校准更新采用 prequential 顺序：先用成熟的旧预测计算并保存分数，再把已成熟记录加入后续校准/训练数据，产生新版本；不得回改历史预测或用未来标签重新计算旧时刻置信度。盲测版本保持冻结。

## 8. 评估标准

所有模型使用同一比赛序列、同一预测锚点、同一可见输入、同一目标构造和同一评分脚本。至少比较持续性基线（状态保持/匀速外推）、规则基线、现有模型和 Jev。

### 8.1 离散概率判断

- 主评分：多类/多标签 Brier score、log loss；类别不平衡时同时报告按类分解结果。
- 校准：可靠性图、ECE 或分箱校准误差、预测区间/集合覆盖率，并报告分箱样本数。
- 排序/覆盖：Top-K recall、关键事件 PR-AUC、固定覆盖率下的风险/错误率。
- accuracy、macro-F1 只作为易读的辅助指标，不作为概率模型的唯一验收条件。

### 8.2 连续位置与联合状态

- 一维/分量位置分布：CRPS 与预测区间覆盖率/宽度。
- 多实体联合位置或状态：energy score；另报区域命中、质心误差和关键目标偏移。
- 轨迹评估同时报告不同地平线上的误差与覆盖率，不能只评最终端点。

### 8.3 统计比较

按局/场次报告宏平均和分布，使用按对局分组的 bootstrap 置信区间比较模型相对基线的分数变化。训练、验证和盲测按正式赛程时间前推分割，并按 `match_id` 整组隔离；所有模型调参与阈值选择只使用训练/验证部分。

## 9. 数据划分与无泄漏门禁

1. 从 `matches` 读取赛区、场次号、局号和比赛开始时间，建立可复现的正式比赛顺序。
2. 以完整对阵 `match_id` 分组进行 rolling-origin 切分：较早比赛训练，随后比赛验证，最后时间段作为冻结盲测。缺少稳定 `match_id` 时，用赛区/场次号重建并校验唯一性。
3. 报告完整记录所有训练、验证、盲测 game_id；不截断清单，不只报告前若干局。
4. 自动扫描特征最大观测时间，必须满足 `max_input_observed_at <= issued_at`；自动扫描所有目标时间，必须满足 `target_at > issued_at`。
5. 检查训练/验证/测试的 match_id、game_id 无交集；窗口边界、标签版本、区域定义和传感器重放器配置写入 manifest。
6. 对抽样锚点提供可审计的输入快照、未来真值和特征来源，供人工抽查时间因果性；人工标签不是运行门槛。

## 10. 验收门槛

- 因果门禁为硬门槛：未来输入特征数为 0；数据切分交叉数为 0；非法预测格式必须显式计为失败。
- 观测门禁为硬门槛：部署特征全部具有来源和可用时间；敌方全局回放坐标不得进入输入快照。
- 预测模型须在冻结盲测上相对持续性/规则基线改善主要 proper score，且按局 bootstrap 的差异置信区间支持改善；否则不宣布预测能力提升。
- 校准门槛按任务独立制定，报告 Brier/log loss、覆盖率和可靠性分箱；不能仅因 top-1 accuracy 上升就上线。
- 行动建议收益单独验收。缺少动作结果的可识别因果评估时，标记为研究建议，不计作已证明的胜率提升。

## 11. 实施拆分建议

本设计落地应分阶段：

1. **状态与观测数据契约**：修正 as-of 对齐和 t=0 行为，建立原始全局真值与部署可见输入分层，确认传感器可见性来源。
2. **未来目标与时间清单**：实现 10/30/60/120 秒目标构造、末段删失和完整按 match_id 时间切分 manifest。
3. **概率模型接口**：建立多时距分类分布、位置分布与预测账本 schema，再接规则基线/现有模型/Jev。
4. **成熟评分与校准**：实现 proper scoring、校准报告、按对局置信区间和只用已成熟预测的 prequential 校准。
5. **行动建议评估**：在历史动作或可信前向仿真可用后单独开展，不与态势预测准确率混报。

每阶段都保留已知基线和版本化报告。当前文档定义目标契约，不代表传感器重放器、概率预测头或因果行动评估已经实现。
