# RMUC 2026 大模型局势分析系统 — 设计文档

- **日期**: 2026-09-07
- **类型**: 架构设计（Architectural）
- **状态**: 待用户审查（v2，含三引擎分层）
- **数据**: `rmuc_2026_region_dataset.sqlite`（613 局 / timeseries 401 万行 / events 147 万行）

---

## 1. 目标与任务分解

借鉴 TDT（东北大学）冠军思路，用**大模型 + 博弈 + 强化学习**做比赛局势分析，从官方全场数据观测物理行为，输出宏观决策。

### 1.1 基础考核（达线目标）
- **输入**: 处理过的全场数据构建的 `WorldState`
- **输出**: **哨兵**的宏观决策，3 状态 —— `def` / `hitbuilding` / `cruise`
- 对齐 TDT 雷达意图映射：`DefendBase→def`、`AttackOutpost→hitbuilding`、`Patrol→cruise`

### 1.2 进阶任务（promax）
- **输入**: 针对新规则调整后的数据
- **输出**: **每台机器人**的更详细宏观决策，**严格输出结构化数据**
- 覆盖 6 类作战单位（英雄/工程/步兵3/步兵4/空中/哨兵）。**分层 schema**（详见 6.2）：
  - 顶层**全局模式** `均衡/进攻/防守`
  - 每单位**四通道**：`目标对象 + 移动/导航 + 是否开火 + 风险等级`

### 1.3 已确认决策清单
| 决策项 | 结论 |
|---|---|
| 任务范围 | 基础(哨兵3状态)为里程碑，进阶(6类×4维度)为扩展 |
| 标签来源 | 规则启发式全自动 → **升级：RL self-play 最优动作作更优弱标签** |
| 运行环境 | 本地 RTX 5060 8G（Blackwell）|
| 模型 | Qwen2.5-3B 甜点位，1.5B 保底 |
| 方法路线 | A：提示词先跑通 → LoRA 微调提升 |
| 分区 | 不规则战术分区（场地先验骨架 + 行为事件校准），非网格 |
| 行为树 | 作为**上下文先验**，在线挖掘双方战术偏好 |
| **核心引擎** | **三引擎分层融合**：LLM(语义+接口) / 博弈论(意图选择) / RL(策略学习) |
| **RL 环境** | **PettingZoo 多智能体**（2D 极简） |

## 2. 三引擎分层架构（本设计核心）

```
┌─ ⑤ 语义理解层 ── LLM (Qwen2.5-3B) ────────────────────────┐
│  看懂WorldState / 长程规划 / 结构化决策输出(对接状态机)          │
├─ ④ 意图选择层 ── 博弈论 (Fictitious Play / Regret M.) ─────┤
│  建立意图 payoff 矩阵，推演对手最优反应，求解对抗性最优意图        │
├─ ③ 策略学习层 ── RL · PettingZoo MARL (2D极简) ────────────┤
│  self-play 学"什么意图组合能赢" → 强策略 = 策略先验 + 标签来源    │
├─ ② 环境状态层 ── WorldState / Zone (统一表示) ─────────────┤
├─ ① 数据层 ── SQLite ──────────────────────────────────────┘
```

**分工原则**（不互相替代）：
- **RL** 学"什么序列能赢"（无标签、self-play、胜率驱动）→ 提供**战术偏好**与**更优弱标签**。
- **博弈论** 学"选哪个意图"（对抗推演对手最优反应）→ 提供**意图选择策略**。
- **LLM** 学"看懂 + 落地"（语义映射、长程规划、结构化输出）→ 提供**理解与接口**。

**闭环**：RL 在 2D 环境自练长出的强策略，既当作 LLM/决策的**先验上下文**，又可生成**离线蒸馏标签**（比规则启发式可信）。博弈论在与策略库/对手模型交互中更新。三者在 `② WorldState/Zone` 这一统一表示上协作。

## 3. 系统数据流

```
 SQLite(401万行/147万事件)
   → ① 特征采样(每3s决策点+15s趋势) → 约8.5万样本
   → ② WorldState 构建(Zone语义化+四层)
   → ③ 标签生成(规则 + RL蒸馏弱标签)
   → ④ 决策引擎(LLM || 博弈论 || RL 策略) 
   → ⑤ 评测(三分类/合规率/状态条带图)
```

**模块职责**：①降维、②语义化、③标签、④决策、⑤评测。每模块可独立测试；先用单局跑通再扩全量。

## 4. WorldState 构建（Zone 体系）

- **时间粒度**: 决策点每 ~3s，附近 15s 趋势（方向/血量变率/发弹率）。
- **空间语义化**（代数关键约束：建筑坐标=0、受击无攻击方、全局坐标系有基准偏差）：
  **分区 = 场地先验骨架 × 行为事件校准**，非几何网格：
  - 骨架（预置 RMUC 结构，用户可按真实点位校准）：基地区/前哨站区/能量机关区/高地区/飞镖区/中央争夺带。
  - 校准：用建筑受击时刻的**攻击方位置**、增益/能量机关激活位置反推热点，修正边界。
- **每台机器人的综合状态**:
  ```jsonc
  { "robot":"哨兵(红)", "zone":"Z7_敌方前哨站区", "norm_xy":[0.62,0.31],
    "intent":"attack", "target":"前哨站", "risk":"high", "move":"推进" }
  ```
- **四层语义**: 静态地图层 → 动态目标层(Zone+归一化坐标) → 战局状态层(血量/功率/热量/易伤/金币/发弹率/建筑血量) → 语义态势层(`base threat / enemy trend / reachable / lost target`)。

## 5. 标签生成

### 5.1 哨兵三分类（规则启发式 + Zone 主证据）
| 标签 | 主信号 | 辅助 |
|---|---|---|
| hitbuilding | 哨兵在敌方前哨站/基地区 | 开火+建筑受击时窗对齐；枪口朝建筑区 |
| def | 敌单位逼近己方建筑区(己方建筑受击/敌入半场) | 朝威胁开火、留守 |
| cruise | 上述不显著 | 中央争夺带/己方半场游走 |

去噪：连续状态段平滑(≥N秒判切换)、弱信号不当真值硬训、可视化抽检。

### 5.2 升级标签来源 —— RL 蒸馏
- PettingZoo 2D 环境 self-play 学出强策略，对每个 WorldState 取 RL 最优动作，作为**比规则更可信的弱标签**。
- 规则 + RL 蒸馏**双源互补**，用置信度融合/冲突标记，交给 LLM 矫正。

### 5.3 进阶任务弱标签（分层）
同套 Zone 体系扩至：**全局模式** + **每单位四通道**(目标/移动/开火/风险)，由 Zone+附近单位/建筑+血量金币趋势规则推导。

### 5.4 跨单位迁移标签（借鉴 RMUC-OfflineRL）
从**全单位混合数据**学"状态→行为"映射，按状态匹配迁移到目标单位（尤其哨兵），突破单一单位行为树数据的天花板；与 5.1 规则标签**双源互补**（置信度融合/冲突标记），详见 6.6。

## 6. 决策引擎（快慢两环 · 三引擎协作）

> **实时性约束**：LLM 单次推理约 2~5s（Qwen3B 量化），无法进毫秒级实时环。故按**时延预算**分成快慢两环：LLM/博弈论做**慢环战略规划**，行为树/状态机/规则/RL 网络做**快环实时决策**。既保留"大模型做局势分析"的考核点（慢环角色），又满足实车响应。

### 6.0 两环总览
```
慢环(秒级/异步)  WorldState+历史 → LLM+博弈论 → 全局模式+各单位策略意图 → 写黑板
                    ↓ 策略参数/边界(事件驱动: 建筑被毁/能量机关/飞镖开/前哨站掉血)
快环(毫秒级)    WorldState快照 + 黑板策略 → 状态机/行为树/Rule+RL → 立即动作(去哪/打谁/开火)
```
**黑板**：慢环写、快环读的共享策略区（当前全局模式、各单位意图、优先级、是否易伤）。
5 条借鉴/改进各归正确一环：④记忆→慢环输入；①③分层 schema(改名"策略意图")→慢环输出、快环上下文；⑤校验→快环；②迁移标签→训练标签层。

### 6.1 慢环 · 战略规划层（LLM+博弈论，异步）
- 输入：WorldState + 决策记忆(④：历史全局模式/各单位意图)；输出：**全局模式(攻/守/均衡) + 每单位策略意图(目标/移动/开火/风险)**(即①③的分层 schema，改名"策略意图")，写入黑板。
- **触发**：定时(5~10s) **或事件驱动**(建筑被毁/能量机关激活/飞镖开/前哨站掉血/血线剧变)——大变局立即响应，平稳时不烧 GPU。
- 博弈论在此做对抗性"选哪个模式/意图"(payoff+Fictitious Play/Regret Matching)，作为 LLM 对抗先验。
- 阶段① 提示词基线；阶段② LoRA(int4/8bit+梯度检查点)微调 3B，显存吃紧降 1.5B(慢环只需大局观，可再小)。

### 6.2 快环 · 实时执行层（毫秒级，不过 LLM）
- **行为树/状态机 + 规则**(继承 TDT/北理/MASMP 以可靠性换实时)：读黑板策略 + 当前 WorldState 快照，约束解码到**确定性动作**。
- **可行性校验(⑤)**并入此环：血量/热量/弹量/是否易伤/前哨站状态过滤不可行动作(如"哨兵血<20% 禁止进攻，改回防")。
- 可选：RL 蒸馏的**小决策网络**替代部分规则，黑盒但更快。

### 6.3 性能工程
- **LLM**：INT4 量化 + KV cache + 结构化解码(JSON mode 省无效token) + **相似状态指纹缓存**(状态未大变复用上次决策)；必要时降 1.5B。
- **数据**：慢环用 polars/numpy 向量化预计算、增量更新；快环只取当前快照，**不做历史聚合**(历史归慢环)。
- **异步**：快慢环并跑，慢环结果热更新黑板，不阻塞实时输出。

### 6.4 RL（策略学习 · PettingZoo MARL）
- 2D 极简环境；单位简化为点/圆；PPO self-play；仅学**宏观意图动作空间**。
- 产：**蒸馏策略网络**(可入快环) + **策略先验**(助慢环) + **蒸馏标签**(汇 6.5)。

### 6.5 标签层（跨单位迁移 + RL 蒸馏）
- 全单位迁移标签(④2→改进②，借 RMUC-OfflineRL) + RL 蒸馏标签 + 规则标签 **多源互补**(置信度融合/冲突标记)，供微调。

### 6.6 对接状态机（实车 DecisionRequest）
- 快环输出(Zone+意图)即状态机状态；转移 = `PUSH-IN / FALLBACK / 绕行`；映射 `StateEnum / EventEnum / transitions`。
- 统一接口 `DecisionRequest`，实车单主执行器。

## 7. 评测与可视化

- 基础：三分类 准确率/F1/宏平均；结构化输出合法率。
- 进阶：分层 schema 合规率（全局模式+四通道）；字段抽样人工评分。
- 校验层：可行性校验**通过率**；LLM 输出被规则层修正的比例。
- 连贯性：决策记忆下**相邻决策点冲突率**（检验状态机切换是否平顺，对标 MASMP）。
- **性能/时延**：慢环触发时延、**快环单次决策时延**(目标 <100ms)、黑板更新延迟、端到端决策频率、全程 GPU 占用。
- RL：2D 环境内胜率/对局分析；蒸馏标签与规则标签一致性。
- 可视化：哨兵状态条带图(规则 vs 模型 vs RL)、行为树路径图、分区热力图、RL 对局重放、黑板策略时间线。

## 8. 里程碑路径

- **M0**：单局数据管线(①→③)，画哨兵状态条带图，确认 Zone/标签合理。
- **M1(达标)**：慢环战略层(6.1)提示词基线，WorldState→哨兵3状态；接**快环行为树+可行性校验(6.2)**，评测达标(含时延)。
- **M2**：RL 2D 环境 + PettingZoo self-play → 蒸馏策略网络(入快环) + 跨单位迁移标签(5.4) → LoRA 微调；LLM 加决策记忆、异步黑板(6.3)。
- **M3(进阶)**：博弈论意图选择 + 分层 schema(全局模式+每单位四通道) + 行为树先验(含全局模式) 整体整合到快慢环。

## 9. 风险与后续细化

| 风险/待办 | 说明 |
|---|---|
| 分区真实性 | 依赖场地先验，需用户补真实点位或用 RMUC 结构校准 |
| RL 简化失真 | 极简2D只学意图不学控制；真实规则(热量/易伤上限)需在环境建模或交由 LLM 把关 |
| RL 训练成本 | MARL self-play 机器成本(CPU)；为可控限制动作空间为宏观意图 |
| 博弈论 payoff | payoff 矩阵需依赖 RL/对手模型估计，需迭代校准 |
| 进阶 schema | 无官方标准，按4维度设计，待征询确认 |
| 显存/泄漏 | 3B LoRA 需量化小batch，预案1.5B；训练/测试按 game_id 切分防泄漏 |
| 已有同类工作 | 见第10节调研；RMUC-OfflineRL 已用同一数据集做纯RL全兵种决策（未用LLM），需差异化 |

## 10. 调研与对标（2026-09）

> 公开资料中，**尚无任何战队给出"大模型做高层战术决策"的完整开源方案**。现有工作要么止步于"行为树+人工规则"，要么走纯RL。这既是行业公认的空白，也是本项目的差异化机会。

### 10.1 直接相关项目

| 项目 | 机构 | 要点 | 与我们的关系 |
|---|---|---|---|
| **RMUC-OfflineRL** | 北师香港浸会·Navigator（开源） | 官方数据集全兵种**离线RL**；1Hz战术决策，161维状态，动作三通道(去哪/打谁/能否开火)；IQL/BC/Decision Transformer；敌方目标选对率74.6%；**用人类步兵数据迁移训哨兵**(+0.341 vs +0.215) | 用同一数据集做纯RL(无LLM)。其"人类数据迁移哨兵"可借鉴到我们的标签增强 |
| **北理追梦·哨兵导航**(RM2026开源) | 北京理工 | 战术层 BehaviorTree.CPP，分**均衡/进攻/防守**三模式，但模式靠**人工硬编码条件**；自认"LLM高层决策是明显欠缺"，并指出**东大已用LLM整合比赛信息参与全局策略生成** | 印证"LLM出意图→行为树执行"层级；其"人工条件"正是我们要用LLM替代的 |
| **TDT 雷达**(东北大学, RM2025开源) | 东北大学 | 三层ROS2雷达，为哨兵提供"宏观决策"+高维信息；RMUC2026全国总冠军，哨兵决策/定位/导航突出 | 直接对标；具体行为树/状态机细节未公开，但概念与我们一致 |
| **武科大崇战** | 武汉科大 | 开源哨兵决策+导航系统 | 决策层可参考 |

### 10.2 学术前沿（LLM/RTS 决策）

| 论文 | 要点 | 印证 |
|---|---|---|
| **MASMP** (arXiv:2510.18395) | 自然语言prompt模拟**状态机+行为树**+轻量记忆(战术/优先单位)；星际2 Simple64 对最难AI(Lv7)**60%**，baseline LLM为0% | 直接印证图2"状态机+LLM"：解决LLM幻觉与"Knowing-Doing Gap"，FSM式可靠+LLM语义 |
| **Adaptive Command** (Ma et al., StarCraft II) | LLM战略顾问 + **行为树执行器**，实时策略调节(Behavior Modulators) | 印证"LLM策略→BT执行"范式 |
| **Tactical Reward Shaping** (ROBIO 2019) | **Stag Hunt(猎鹿博弈)**奖励塑形引导机器人协同攻击同一目标 | 印证**博弈论**在RoboMaster可直接用 |
| 中科院·RMAI2020 | 2v2视为**零和博弈**，多智能体DRL+行为决策树，Gazebo/星际/PyGame仿真 | 印证"博弈论+行为树"组合 |
| 哈工大·哨兵 | 哨兵决策建模为**MDP**(路径/追踪/回防/补给)，雷达-哨兵多机通讯 | 印证 RL/MDP 可行性 |
| 大疆·**RoboRTS** | 多智能体协同框架：分层架构、对手建模、MCTS、策略优化 | 印证博弈论/对手建模方向 |

### 10.3 对我们的启示（融入设计）
1. **行业共识层级已成形**：`LLM出意图(想做什么) → 行为树/状态机(能做什么/可靠执行) → 底层控制`。与我们的三引擎(LLM语义+意图→接口)、行为树先验完全一致 → 不做偏离。
2. **差异化 = 用 LLM 替代"人工条件判断"**：北理的三模式靠人工写规则；我们用 LLM 从WorldState直接推断 `def/hitbuilding/cruise` 及6单位决策，自动化且可扩展。
3. **标签增强借鉴**：RMUC-OfflineRL 用人类步兵数据迁移哨兵的做法，可加入我们的规则标签（混合单位标签 + RL蒸馏），比纯规则更可信。
4. **空白即机会**：考核要求的"大模型局势分析"，公开无完整开源方案。我们的"LLM语义化 + Zone分区 + 博弈论 + RL蒸馏 + 行为树先验"是当前已知最完整的高层决策路线。
