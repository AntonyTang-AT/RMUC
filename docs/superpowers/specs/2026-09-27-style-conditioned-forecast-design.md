# 按打法分型的时序预测与公平评估设计

日期：2026-09-27
状态：待用户审阅；本文件是设计规格，尚未获批实现。
范围：第一阶段——确认可泛化预测信号，并评估“先估计打法、再选择/融合相应预测专家”是否改善结果。

## 1. 目标与背景

当前时序预测在标签时间映射、观测因果性和按整场分组方面已有较好的基础；这次审计未发现明显的未来标签穿越。不过，当前 GRU 在 10/30 秒全局态势上弱于持久性基线，生产融合因此把这两档模型权重置零。数据集有 613 场比赛和 96 支队伍，但没有基于队伍行为的打法分型器，也没有对“训练和调参时都未出现过的队伍”做独立泛化验收。由此不能把当前结果解释成网络已学会适用于不同队伍的短期策略规律。

本阶段回答一个具体问题：**根据预测时刻之前可见的敌方行为估计其打法分布，并将这个不确定的打法信息交给预测模型，能否在未见队伍和完整留出比赛上稳定优于当前通用模型及简单基线？**

本阶段是实验候选，不改变生产模型默认，不更新已存在检查点，也不接入实时运行时。只有公平评估证明增益后，才进入在线校准和对手行为反演阶段。

## 2. 设计约束

1. 每条特征都必须在预测时点可用。禁止用整场结束后计算的队伍画像、比赛结果、未来轨迹或未来规则标签推断当前打法。
2. 风格推断面向当前可观察的对手行为，不把学校名称或队伍 ID 作为预测输入。稳定身份不是部署可依赖的传感器字段。
3. 红蓝观测侧保持对称；同一场比赛的红、蓝样本必须留在同一个外层折/集合。
4. 时序窗口高度重叠，统计推断以完整比赛为单位；比赛内部先分别算红、蓝，再做两侧等权的配对结果。
5. 风格聚类、特征标准化、路由温度、专家收缩与概率校准都只能在外层训练数据的内层分组验证中拟合。外层验证只作冻结确认，最终测试在协议冻结前不可查看。
6. 风格不确定时必须回退到通用模型；不得强行给新队伍分配高置信硬标签。

## 3. 推荐架构

采用**共享通用模型 + 少量风格条件专家 + 软路由**，不为每个簇训练一个完全独立的大模型。

### 3.1 因果风格表示

对每个预测时点，基于其截至当时的雷达可见历史构造短摘要，例如：

- 敌方编组质心、离散度、功能区占用与向对方区域推进的速度/持续时间；
- 各兵种当前可见数量、存活/HP 概况、目标可见覆盖率及观测年龄；
- 可观测的区域争夺、回撤、接敌和资源活动迹象；
- 只在协议允许且有可靠来源时使用的队伍资源变化。

每个量都带可用性/覆盖率信息。受遮挡、雷达未发现或协议不支持的值保持未知并附带 mask；不得把“暂时看不到”当成阵亡、未开火或没有资源。

### 3.2 风格后验与专家预测

在每个训练折内，只用该折训练比赛的因果摘要拟合少量候选风格原型（预注册 `K=2` 和 `K=3`）。对每个时点输出风格概率向量、有效观测量和不确定度。预测器用共享主干加轻量专家输出；以风格概率软融合专家，并用训练折内选定的收缩系数融合回通用输出：

`P(y | x) = (1 - r) P_global(y | x) + r Σ_k P(style=k | x) P_k(y | x)`

其中 `r` 由内层整场验证选择，并允许在覆盖不足或风格熵过高时趋近 0。风格簇的名称只用于报告解释；簇号可在不同折间置换，不能把同名簇假设为天然一致。

### 3.3 比较候选

在相同训练折、相同观测字段、相同目标标签和相近训练预算下配对比较：

1. 持久性基线及已登记的简单趋势/速度基线；
2. 当前通用 GRU/LightGBM 候选；
3. 只增加因果行为摘要、但不分型的通用模型；
4. `K=2/3` 的软路由风格条件模型。

第 3 项用于区分“增加行为摘要有效”与“风格分型本身有效”，防止将任意特征增益误称为分类增益。

## 4. 数据切分与训练合同

### 4.1 两种泛化问题

- **时间后推评估**：按整场 `match_id` 时间顺序切分；只允许使用预测点之前的历史。回答对已参赛队伍后续比赛能否适应。
- **队伍隔离评估**：预先按队伍 ID 选定外层留出队伍；所有涉及这些目标队伍的比赛都从训练和内层验证中排除，红蓝双方仍作为整场一组。回答没有见过该队时能否由当场雷达前缀识别行为。

两类结果分别报告，不混成一个总分。若队伍对阵图导致完全双队伍隔离后有效样本不足，则以“目标对手队伍隔离、整场比赛隔离”为主要可执行合同，并清楚报告另一侧队伍的训练历史覆盖率；不能声称双方均为未见队伍。

### 4.2 拟合边界

外层每折先按完整比赛隔离训练与留出。标准化参数、风格原型、K 的选择、软路由温度、通用输出收缩系数、类别/样本权重和概率校准均只在该外层训练集内完成，并用内层整场分组交叉验证选择。每个外层留出比赛在其自身时间序列中可因果地更新风格后验，但不得重估风格原型或模型权重。

标签保持现行合同：输入截止 `observed_at <= issued_at` 且 `received_at <= issued_at`；未来目标使用精确 `issued_at + horizon` 时间点；没有目标时记为删失，不插值、不取最近秒。红蓝样本使用同一预测时点合同。

## 5. 评估指标与晋升条件

### 5.1 分类与概率

对全局态势、敌方趋势和敌方区域，按任务/时距分别报告 Accuracy、固定类别 Macro-F1、Balanced Accuracy、类别召回、Brier、LogLoss、校准误差与可评分覆盖率。先在每场每侧汇总，再对红蓝等权；配对差及置信区间按完整比赛 bootstrap。

对位置/区域预测分别报告米制误差、区域命中率和覆盖率，不用类别 Accuracy 代替连续误差。按状态转移与状态持续两组拆分，防止高持久性样本掩盖转移失败。

风格分型本身是潜变量聚类，不以训练集聚类纯度或自造风格标签的一致率作为成功标准。应报告簇稳定性、各簇覆盖/有效队伍数、路由熵，并以留出预测质量的配对差作为主要证据。

### 5.2 冻结晋升门槛

风格模型只在以下条件全部满足后成为候选默认：

- 在预先声明的主要任务/时距上，优于通用模型与持久性基线的整场配对差具有正向证据；
- 主要决策指标的 Macro-F1/Balanced Accuracy、关键类别召回或概率分数没有超出预先容忍范围的退化；
- 红蓝方向一致，结果不是由少数队伍、少数比赛或极低覆盖簇驱动；
- 时间后推和队伍隔离两种结果分别披露，且队伍隔离评估的覆盖率可接受；
- 在未触碰的最终比赛集上只做一次冻结确认。

阈值和容忍范围应在训练/内层折上根据业务损失与测量噪声确定，在打开最终测试结果前冻结；不得因测试结果不满意而继续调参。

## 6. 与后续在线学习的接口边界

本阶段预测接口应额外输出 `style_posterior`、`style_entropy`、`style_coverage`、`expert_contributions` 和 `fallback_reason`，并保持既有预测字段向后兼容。每局风格后验从宽先验开始，只能由独立的、当时可见的行为证据逐步更新；模型自己先前预测的 top 类别不得作为新的监督证据。

后续阶段再设计单独的 match-local feedback coordinator：登记确定性预测 ID、精确 `mature_at`、模型版本、输入哈希与概率；在精确未来观测成熟后才评分并更新该局校准/专家权重；比赛边界清空待评分记录、风格后验和校准状态。局内先调整输出概率或专家权重，不在线梯度更新网络参数。建筑掉血、受击等结果只作结果证据，不归因到单个敌方机器人或意图。

## 7. 数据驱动的字段/时距权重路线

后续评估层按**指标 × 时距 × 观测覆盖**独立计算模型相对适当简单基线的交叉验证 Skill Score，并附带整场 bootstrap 区间。分类/概率任务以 Brier、LogLoss、Macro-F1/BA 与覆盖为主；连续量以 MAE/RMSE/相关系数与基线比较为主。相关系数只描述同步变化，不单独作为保留依据。

- 重复整场评估显示相对基线没有可用增量且区间排除最小实用效应：该字段/时距从主评估权重中剔除或只显示为探索项。
- 有稳定但有限的增量，或只有某一类/某阵营有效：保留为低权重概率/趋势参考，并标注适用范围。
- 跨整场折稳定优于基线、覆盖足够、校准与类别质量不过度退化：按预先声明的决策损失赋予较高权重。

权重不从单一全局相关系数或同一 validation 上搜出来。具体公式、最小实用效应、覆盖阈值和是否随在线校准动态变化，作为独立阶段规格冻结，避免在本阶段把模型选择和验收权重混为一谈。

## 8. 失效处理与安全回退

- 新比赛或雷达覆盖低时，风格后验保持宽；软路由强度归零并输出通用预测。
- 风格簇有效队伍数不足或内层路由不稳定时，候选不晋升，继续使用通用模型。
- 未来标签删失、机器人阵亡/重生或敌方不可见时，分别使用既有删失/生存语义；不把缺测改成负类。
- 任何外层训练—验证—测试比赛/队伍重叠、预测 ID 不稳定或目标时间不精确，都使该次结果无效并停止报告晋升结论。
- 实验产物使用全新候选目录和独立报告路径；不覆盖生产 checkpoint、数据集 manifest 或用户现有回放文件。

## 9. 验证清单

- 数据测试：因果前缀截断、缺失覆盖 mask、红蓝映射、同场同折、目标时间精确及删失。
- 风格测试：原型只从当前外层训练集拟合；簇标签可置换而预测不变；高熵/低覆盖输入回退通用输出。
- 学习测试：通用模型、加摘要模型、风格专家模型在完全相同的折/标签/基线下配对；检查输出概率和位置指标 finite、归一化、版本可追溯。
- 统计测试：按比赛聚类 bootstrap，比赛内红蓝等权；团队隔离清单与运行报告一致；最终测试只读一次。
- 运行测试：同一历史前缀重复运行得到相同风格概率与预测；模型加载失败或风格模块不可用时不阻断通用预测。

## 10. 已知风险与开放实现决定

- 每队比赛数量不均且单队游戏内窗口高度相关；训练采样和 bootstrap 必须避免由高频队伍主导。
- 雷达遮挡造成的风格推断误差可能被模型误当作战术变化；覆盖率必须作为输入与分层报告维度。
- 潜变量簇跨折没有天然编号对应；解释报告需要通过原型行为摘要对齐，不可直接比较数字簇 ID。
- 多任务、多时距会带来多重比较。主要任务/时距必须在看外层结果前声明，其余作为探索性。
- 原始队伍身份并非实车可用输入；任何跨局经验记忆必须等身份可靠性、隐私和数据合同另行确认，不属于本阶段。
