# 预测输入可见性字段契约

当前训练集采用 `rmuc_2026_referee_radar_protocol_v1`，依据 RMUC 2026 通信协议和项目 SQLite 实际存在的字段筛选。

## 每个视角都能使用

| 数据 | 处理方式 |
|---|---|
| 局号、比赛顺序、赛区、双方学校 | 作为比赛上下文；胜负字段不进入输入 |
| 当前时间、比赛剩余时间 | 可用，按比赛状态字段构造 |
| 己方机器人类型、编号、阵营 | 保留 |
| 己方位置、朝向、底盘功率、血量/最大血量、热量、累计发弹、队伍金币 | 保留为己方状态 |
| 己方建筑血量与状态 | 保留为己方状态 |
| 敌方机器人类型、编号、阵营 | 保留为雷达目标身份 |
| 敌方有效 XY 坐标 | 保留；`x=y=0` 按协议解释为未发送，位置字段省略 |
| 敌方当前 HP | 保留；无人机 HP 在协议对应槽位中没有定义，省略 |
| 敌方队伍总金币、剩余金币 | 保留为宏观状态 |
| `是否易伤` | 保留为雷达标记状态，不作为唯一坐标可见条件 |

## 当前不进入输入

| 数据 | 原因 |
|---|---|
| 敌方 z、高度、枪口朝向、底盘功率、热量 | 雷达协议字段中没有这些细节 |
| 敌方累计 17mm/42mm 发弹、最大血量 | 数据集列是裁判/回放字段，协议对应的余弹/状态包没有被记录，不能用累计发弹代替 |
| 敌方基地/前哨站的逐帧内部细节 | 当前协议位置包针对敌方机器人；建筑真值用于未来标签和评分 |
| 未来时刻任何字段 | 违反因果截断 |
| `matches.胜方` | 只有比赛结束后才知道，属于标签/核验信息 |
| `events` 中未经事件类型映射的全量记录 | 事件有全队广播、己方广播、雷达专用等不同接收范围，需按协议逐类映射后再加入 |

## 规则依据和数据边界

RMUC 2026 通信协议列出雷达接收的敌方位置、HP、余弹、队伍宏观状态和增益字段；本项目数据只完整提供前四类中的位置、HP、队伍金币子集，未提供余弹和完整增益包。因此当前结果命名为 `visibility_masked_replay`，表示按规则字段筛选的回放，不表示已经拥有原始车载网络包、延迟、丢包和噪声。

代码入口：`data/radar_visibility_replay.py`；全量提取：`eval/prepare_forecast_dataset.py`。
