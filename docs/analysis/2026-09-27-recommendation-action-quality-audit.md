# 单体建议语义与动作指标复核（开发样本）

## 范围

- 只使用原前 8 场、红蓝双方、每 3 秒建议时点；取准确的 t+3s、t+10s 行。未访问 test。
- 命中率、路线和血量是历史行为代理，不证明机器人收到或执行建议，也不证明建议造成结果。
- 目标 HP/存活变化受全场其他机器人共同影响，必须视为混杂的观察结果。

## 根因与修正

1. 哨兵原先只因位于己方前哨/基地/其他己方区域，就被打上 `guarding_outpost`、`guarding_base` 或 `patrol`，进而生成“保持防区”行动。这把地理位置先验误当成明确任务。现在 `defense_status=unknown`，位置只记入 `defense_role_prior`，`defense_evidence=functional_zone_prior`，并明确 `role_prior_only`；没有明确防守任务或设施告警时不下可执行建议。
2. `possible_attack` 只代表可见距离推断，不等于已有掩体、攻击命令或追击路线。现在建议为“先留在当前区域确认目标，不单独追击”；首步为本区、0 米、移动目标为 null。敌情确认因缺未来雷达可见性字段，评估显式为 unknown。
3. 攻击目标所在区与我方移动目标此前共用 `target_zone`。现在攻击的空间移动目标为 null；路线评分不会把敌方当前所在区当成我方路线终点。
4. 配对 bootstrap 原先把每个兵种的分数等权平均，和展示的建议事件池化命中率不一致。现在先在每场、每方内按建议事件计数汇总，再按比赛聚类 bootstrap，红蓝齐全的比赛等权平衡。
5. 输出补充目标 ID/兵种/距离、首步区/到区中心直线距离、路径、触发与停止条件。距离只是到区域中心的直线估计，不是行驶距离或 ETA。
6. 回放单位展开信息增加建议评分卡：路线可行性、执行证据、动作匹配的后果指标、因果可识别性分开报告。全局主文压缩为三段短文，详细单位与模型证据仍保留在结构化展开区。

## 复核结果

8 场样本现在不再把守防先验当作建议，因此守防建议样本数为 0；这不代表防守任务不重要，而是现有输入不足以识别“正在执行防守命令”。可能交战提醒共 4,088 条 t+3、4,033 条 t+10 可核对记录：留在当前区的实际比例为 72.1% / 58.2%，自身存活率 98.6% / 95.4%。这两项只能说明行为与提醒相容的程度；敌方确认指标仍为 unknown，不能据此评价掩护有效性。

| 动作 | t+3 观察 | t+10 观察 | 解释 |
|---|---|---|---|
| 确认疑似目标、不单独追击 | 当前区保持率 72.1%；自身存活 98.6%；自身 HP 比例变化 −1.77 pp | 当前区保持率 58.2%；自身存活 95.4%；自身 HP 比例变化 −4.64 pp | 雷达未来可见/确认与掩体字段缺失，敌情确认 unknown；不按目标区命中评估 |
| 继续压制已识别目标 | 自身存活 98.8%；目标存活 77.8%；目标 HP 比例变化 −6.44 pp | 自身存活 95.1%；目标存活 77.2%；目标 HP 比例变化 −9.82 pp | 目标伤害/阵亡受所有参战单位影响，不归因于建议 |
| 低血量撤离 | 自身存活 94.9%；自身 HP 比例变化 +1.18 pp | 自身存活 88.6%；自身 HP 比例变化 +8.09 pp | 区域方向/路线指标只表示是否向建议目标靠近；观察性指标，不证明撤离建议带来收益 |

低血撤离目标区命中：t+3 4.68%，t+10 4.19%；实际与建议目标相比 stay-put 的红蓝均衡、按游戏配对命中差分别为 +4.55 pp（95% CI +2.65 到 +6.63）及 +3.88 pp（+1.06 到 +6.91）。该任务本身要求离开起始区，所以后续目标区命中是偏苛刻的指标；不得把其当作撤离是否成功。更匹配的安全指标应是实际控制器撤离命令、存活/承伤和到安全点时间，当前命令/设施日志缺失。

评分卡覆盖（534 条低血撤离、890 条攻击、4,088 条疑似目标确认建议）：撤离路线图合法率 534/534（100%，仅验证功能区邻接，不是到达时间或成功概率）；无移动建议的可行性标记为不适用。3 秒后果指标覆盖率为 100%；10 秒为 98.5%–100%。没有任何动作有控制器命令/确认日志，故执行维度一律 unknown（coverage 0%，unknown=全部已发建议）；因果收益均为 not_identifiable（coverage 0%）。位置、HP 与目标状态只作历史观察结果，不代替命令执行或策略收益。

### 两个可展示的单体建议例子

1. **疑似接敌确认**：机器人在场地开放区，疑似目标为蓝方步兵3，直线距离约 8.67 米。建议留在当前区确认，不追击；首步仍为场地开放区（0 米）。触发：出现明确开火/弹药变化，或目标进入有效攻击范围；停止：目标离开视野或传感器明确无目标。评分卡：无需跨区路线；执行 unknown；未来雷达确认 unknown；因果收益 not_identifiable。
2. **低血撤离**：一个血量 10% 的单位位于蓝上装配区，首步建议到蓝基地，区域中心直线估计约 6.33 米。触发：HP 低于 30%；停止：HP 恢复至 50% 以上或目标区不可通行。评分卡：首步邻接路线合法（100%）；行驶时间 unknown；执行 unknown。这里的 100% 只指区域边图合法，不代表机器人会走到或及时到达。

## 按动作匹配的量化指标与缺口

- 攻击：目标 HP 变化、目标存活/阵亡；当前可从 ID 与精确 HP 评分，但标为混杂观察值。射击是否由该机器人造成，须有开火/弹药/目标日志。
- 防守：关键设施受损、敌人进入关键区时是否留守。当前没有明确任务日志及设施伤害归因，指标为 unknown；位置先验不得冒充已执行防守。
- 资源：抵达矿区、携带资源、回补给区、完成兑换。比赛时序数据没有逐机器人持有资源/兑换字段，指标为 unknown。
- 低血撤离：到安全区/路线进度、存活率、HP 变化。现可从位置和 HP 描述性评分，执行命令和因果收益仍 unknown。
- 所有动作的指令执行率：需要控制器 command/ack、发出/执行时间、拒绝或覆盖原因；当前为 unknown。

## 真实大模型决策质量

当前可视化全局自然语言由 `structured_evidence_template` 规则模板生成，不是 Qwen/Open-JEV 在线生成。历史文件 `_work/eval_new_model.json` 确有微调 Qwen 的 159 个真实推理点（4 场、1 条解码失败）：合法率 100%，与弱 lookahead 标签一致率 56.6%；另报告攻/守决策与 replay 有利度的关联。但文件只有聚合数，没有每条建议及后续动作结果，因此不能按本文的单体行为指标复算。`out_m2/experiments/qwen_jev_full_finetune_report_20260926.md` 是 128 条 Qwen/Open-JEV 全局三态分类留出结果，不是建议文本质量结果；两模型 30 秒准确率均为 39.06%，该任务输出也不含可核验的单体动作/目标。因此目前仍没有可复现的同口径 LLM 建议样本；需保存输入可见状态、模型/adapter 版本、结构化输出、建议动作/目标/理由和后续观测，再按上述动作指标评估。`eval/llm_backtest.py` 虽有运行日志，但没有落盘 JSON 汇总，不能替代逐条建议审计。
