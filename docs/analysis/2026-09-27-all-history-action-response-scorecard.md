# 全历史动作建议分层评分卡（t+3 / t+10）

## 这份审计能回答什么

新增评分卡从 `timeseries` 和事件遥测逐条重建规则/世界状态建议，按**动作标签 × 兵种 × 红蓝方**分层。每条建议分别核对精确的 `t+3s`、`t+10s` 同机器人观测。它把四类证据分开：

1. **路线定义质量**：仅对有移动目标的建议计算首步是否为合法相邻区、所给完整路径是否合法、目标区在兵种/阵营功能区图上是否可达，以及最短合法跳数。分母和 unknown 单列。
2. **行为响应代理**：移动建议同时看剩余合法区跳数是否减少，以及到目标功能区规划多边形的最短距离变化（连续米制，进入目标多边形后记 0）；留守/防守建议看是否仍在原功能区；攻击/确认建议另看窗口内是否有该机器人的发弹事件。它们只描述后来观测到的行为。
3. **自身/目标状态结果代理**：记录自身存活与归一化 HP 变化。目标存活/HP 只在建议时有传感器明确指定的 `target_unit_id` 时评分；最近可见机器人的几何候选不作为实际攻击对象。当前重新计算的全历史建议没有一个满足显式目标链接，所以目标 HP/存活覆盖率为 0，全部保留为未知。即使今后有已确认目标，HP 变化仍受其他单位和事件影响，只能作为观察结果。
4. **覆盖与未知**：精确未来行、未来区域、HP、目标 ID/状态、路径字段缺失均按各自指标列出，不将 unknown 记成失败。数据库没有控制器命令/ack，故执行状态始终是 `unknown`，执行可评分覆盖率为 0%。

所有响应指标都不是建议准确率、命令执行率或建议带来的收益。发弹不等于打中指定目标；目标 HP/存活也不能归因于某一条建议。功能区邻接图是规划级近似，不能代替碰撞检查或真实 ETA。

## 全历史复核结果

脚本运行结果：613 场、红蓝两方、每 3 秒建议时点，共 429,479 条建议；得到 30 个「动作 × 兵种 × 阵营」分层。下表为合并动作层后的描述性比例，分层原始分子/分母及比例指标的比赛聚类区间保存在 JSON。

| 动作 | 建议数 | 精确未来行覆盖 t+3 / t+10 | t+3 响应/代理 | t+10 响应/代理 |
|---|---:|---:|---:|---:|
| 继续攻击可见目标 | 88,981 | 99.3% / 97.9% | 80.7% 有本机发弹事件；自身存活 98.7%；目标存活/HP：无已确认目标，未评分 | 91.1% 有本机发弹事件；自身存活 96.1%；目标存活/HP：无已确认目标，未评分 |
| 留在当前位置确认/掩护 | 310,167 | 99.2% / 97.6% | 74.2% 仍在原功能区；20.7% 有本机发弹事件；自身存活 98.8% | 60.2% 仍在原功能区；41.2% 有本机发弹事件；自身存活 96.0% |
| 低血量撤离 | 30,331 | 99.0% / 97.0% | 目标区最短合法跳数减少率 4.7%；到目标区多边形距离平均减少 0.108 m；自身存活 94.5% | 跳数减少率 3.7%；目标区距离平均增加 0.511 m；自身存活 89.0% |

唯一出现的移动 advice 是低血撤离：首步合法 **30,331/30,331**，完整路径合法 **30,331/30,331**，图上目标可达 **30,331/30,331**。这里的“可达”只表示手工功能区邻接图存在路，不说明物理通行、预计时间或会按建议行驶。撤离的 t+3 距离仅小幅减少，至 t+10 的平均值转为增加；这比“已经执行撤离”的说法更符合观测证据。分兵种/红蓝的数字可能不同，应优先查看 JSON 中分层数据；合并表仅用于概览。

本轮距离平均值字段名按单位明确输出为 `mean_distance_reduction_m`；正数表示接近目标多边形，负数表示远离。自身/目标 HP 变化均按当前 HP / 最大 HP 计算，分层 JSON 给出该比例变化的均值及其样本覆盖。

## 对现有 Qwen / Open-JEV 结果的适用性

本审计评估的是由当前规则状态管线产生的 advice，**不直接给既有 Qwen/Open-JEV 模型结果打分**：

- Qwen 159 点文件只有聚合合法率、弱标签一致率及攻防关联，没有逐点动作/目标/推荐区域；不能恢复按动作、兵种、阵营分层的行为分数。
- Qwen/Open-JEV 128 行是全局态势类别概率探针，不是可执行单位动作；不能映射成单兵 advice，也不能用本评分卡充当模型建议得分。
- `eval/llm_backtest.py` 的 `--rows-out` 能保存逐点输入快照与原始 prompt、原始输出、结构化解析、推理耗时、adapter tree SHA-256、prompt/system hash 和生成配置。它仍没有 base 权重与 tokenizer 文件哈希，也不含未来 outcome；而且该旧回测输入仍是完整比赛回放状态（`legacy_complete_timeseries_current_state_not_radar_masked`），不能视为雷达可见的部署输入。本次**没有**据此生成任何 LLM 动作响应分数。
- 即使将来保存了 LLM 逐点动作，回放行为响应仍只是可观测的响应代理。真实执行需 controller command/ack；因果效益需干预或可信的前向仿真/反事实设计。

要让 LLM 适用同一审计，生成时需落盘每条输入键（game/side/time/unit）、动作码、目标 ID/目标区、推荐路径、有效期限、原文、解析合法性、模型/adapter/checkpoint 与 prompt 版本；评分器随后按原始比赛键只连接精确未来遥测，输出与规则建议一致的路线/响应/结果代理和缺失覆盖率。输入快照必须只含建议时已知信息，未来值只能进入评分器。

## 运行与机器产物

```powershell
python eval/audit_all_history_action_response.py
```

结果写入 `out_m2/all_history_action_response_scorecard.json`。JSON 保留逐分层发出条数、路线分母/unknown、t+3/t+10 各指标分母与比赛聚类 95% 区间。少于 5 场有贡献的分层应标为不稳定；不能只看 pooled rate。该全历史审计是描述性历史回放分析，不是留出集/盲测。
