# 可见区域聚合 + 观测态势分数：validation 一次性开发确认

日期：2026-09-27。按项目指示，在 train-only 特征筛选后冻结 `zone + observable score trend` 特征与 LightGBM 参数，用完整 death-aware train 重训，并在 death-aware validation 一次性评分。validation 曾在此前项目工作中被读取多次，因此这是开发确认，不是盲测或最终验收。脚本没有测试集参数，也没有读取 test 文件；没有根据 validation 调整任何参数、特征或默认模型。

训练/validation 的标签合同均为 `relative_margin_v2_death_aware_hp_le_zero`，两边 game_id 无交集。train 101,410 行、363 场；validation 34,114 行、122 场（受未来标签删失影响，各时距参与评分的行数略少）。train 和 validation JSONL 均逐行与 compact NPZ 按 game_id、side、issued_at 对齐，当前态势重算与 `base_mode` 精确一致。候选特征仅读取当前与历史 `observable`；敌方状态限定在 radar 可见集，不补隐藏敌人；敌方资源字段排除。我方资源来自 sensor 观测。

## 决策

开发 validation 上，30/60/120 秒 Accuracy 高于 direct LightGBM；60 秒的 Macro-F1 和均衡召回也提高。10 秒差异很小且 Accuracy CI 跨零。不同类别并非一致改善：10 秒进攻/防守召回降低，120 秒均衡召回降低 2.50pp。相对持久性，30 秒 Accuracy 明显提高；60 秒准确率提高但宏 F1 没有可靠变化；120 秒宏 F1 没有改善。整体结果有希望，但类别权衡与既往 validation 反复使用都不支持直接晋升 production。保留为有前景的候选，等待一批真正未看过的比赛确认。

| 目标时距 | 此次候选 Accuracy | 用户目标范围 | 达标情况 |
|---:|---:|---:|---|
| 10s | 72.59% | 70–80% | 达到 |
| 30s | 62.42% | 60–70% | 达到 |
| 60s | 59.39% | 45–55% | 高于目标带；需确认评估口径和远期标签意义 |
| 120s | 52.53% | 35–45% | 高于目标带；Macro-F1仅28.10%，均衡召回18.44% |

60/120 秒 Accuracy 高于目标带并不代表整体预测更可靠：Macro-F1 与均衡类召回仍低，尤其 120 秒。后续验收应同时看 Accuracy、Macro-F1、逐类召回和按局区间，不应只用单一正确率。
