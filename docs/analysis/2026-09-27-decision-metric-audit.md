# 决策建议可量化评估：现有数据小样本审计

日期：2026-09-27；低血量分母修复后重算。复现命令：`python _work/decision_metric_audit.py`。原始机器可读结果在 `_work/decision_metric_audit.json`。脚本只读 SQLite，使用雷达可见性适配器构造发出时刻输入，以数据库的精确 `t+3`、`t+10` 行作事后核验。没有改生产推理代码。

## 数据和可评估边界

抽取正式时间顺序最早的 3 个完整对阵，共 8 局。每局分别从红、蓝视角评估：每侧 1120 个 3 秒决策锚点；精确 `t+3` 有 1112 个、`t+10` 有 1096 个；末段 24 个锚点至少一个目标时间不可用。红方 6440 个当前机器人行、蓝方 6720 个；剔除已确认阵亡后有建议的分别为 5777、6084 行。

原库只有 `matches`、`timeseries`、`events`。`events` 包含发弹、受击等结果事件，未发现实际下发的移动/目标/开火指令日志。因此，**无法直接计算“3 秒内首次动作是否与建议吻合”**；可计算的是随后观测到的功能区是否等于建议的第一步区域。两者不能混称。

**关键发现：**修复低血量分母后出现 538 条非原地建议；这批建议全部是“撤向己方相邻区域并减少暴露”。总体 3 秒区域命中率低于保持原区基线，主要由这些撤退建议产生。随机合法区域较低不能作为建议获益证据。100% 的合法性只说明第一步符合区域图，不说明能在指定时间到达。

### 非原地撤退建议的时间与路径核验

| 指标 | 红方视角 | 蓝方视角 |
|---|---:|---:|

| `t+3` 正好在第一步区 | 10/230 = 4.35% | 15/304 = 4.93% |

| 1–10 秒间**曾到达**第一步区 | 24/227 = 10.57% | 30/298 = 10.07% |

本样本的撤退建议把最终目标区设置为相邻第一步区，所以两项到达计数相同。`t+3` 的区域命中可能过早：超过半数机器人已向目标区中心靠近，但尚未跨过功能区边界。因此不能只用 3 秒“到区”验收移动建议。延长至 10 秒后，曾到区的比例仍约 10%，路径后向进度不足 5%；时间窗口偏短不是唯一解释。区中心距离是粗代理，不能代替合法路线长度、实际指令或安全性评价。

按动作类别拆分，非原地建议只有上述“低血量撤退”一类；其他行动类别在本样本中没有非原地第一步，不能据此比较类别优劣。按兵种拆分如下，括号内为 1–10 秒曾到达第一步区的次数：

## 旧评估脚本的适用范围

- `eval/outcome_backtest.py`：用全局完整对局的胜负相关特征训练/验证胜负判别器，再看红方哨兵规则决策发生时的有利度区间。它只支持**关联性**诊断；随机 K 折和全局全程特征不满足赛程前推、部署可见与红蓝对称的决策效果评估。
- `eval/strategy_lag.py`：比较规则头三态与前向窗口位置/建筑血量导出的弱策略标签，能描述规则一致率随滞后变化。其预测头是红方规则口径，`--team 蓝` 只改标签侧，不构成有效双侧比较。
- `eval/llm_backtest.py`：需要 GPU 模型和 adapter，输出模型决策与胜势有利度的关联，仍不检验动作是否执行或是否造成收益；代码中的规则基线数值还是固定常量，应重算后才用于比较。

## 下一步门槛

1. 为每条建议存档 `game_id`、阵营、实体 ID、发出时间、目标/第一步、触发/取消条件和模型版本；到点仅使用新到达的观测核验。
2. 取得真实下发的移动、目标和开火指令，才能计算 3 秒内**动作吻合率**。当前只能报告位置/攻击事件等响应代理。
3. 扩到按赛程分组的冻结盲测，并让红蓝双方完整运行；先比较保持原区、可达随机、既有规则基线，再比较新策略。统计区间按整场对阵抽样，避免把同局两侧和连续锚点当独立样本。
4. 若要声称建议提升血量、资源或胜率，还需可靠的行动日志加可辨识的反事实设计或经过验证的前向仿真。本报告只描述随后发生的变化。
