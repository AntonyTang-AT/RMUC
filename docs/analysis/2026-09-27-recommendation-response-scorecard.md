# 全历史单兵建议响应评分卡

## 目的与边界

本评分卡检查“建议出现后，后续回放中是否观察到与建议方向一致的变化”，用于定位建议是否具体、能否被数据核验。数据库没有底盘控制器下发/确认日志，因此所有单兵建议的真实执行状态均为**未知/不可观测**。下文的“对齐、中性、反向”是响应代理，不是准确率、指令执行率、建议有效率或因果收益。

## 数据范围与计分口径

- 全量扫描 `timeseries` 表中 613 场比赛，覆盖红蓝视角；建议每 3 秒生成一次，只依据当前时刻的雷达快照生成；后续观测严格取 t+10s 和 t+30s 的精确时间行。
- 共记录 429,479 条具有单兵动作建议的锚点，形成 30 个「建议类型 × 兵种 × 阵营」分层。样本中的建议涉及英雄、工程、步兵3、步兵4、哨兵、空中；没有出现的动作×兵种组合代表此数据集没有生成该建议，不代表该兵种没有对应任务。
- 每个窗口的“可计分数”只包括精确未来行存在且动作响应指标可计算的建议。覆盖率=可计分数/发出建议数。缺少未来行、位置/区域或目标时在 JSON 的 `unscorable_reasons` 中列出，不计作中性或反向。
- 移动建议：到目标功能区规划多边形边界的最短距离变化，进入多边形后距离记 0；减少超过 0.05 地图单位记对齐，增加超过阈值记反向，其余中性。另保留到区域中心的距离变化，仅作诊断。功能区是规划级近似多边形，非毫米级 CAD。
- 留区建议：看是否仍在签发建议时的功能区。留在原区记对齐，离开记反向；没有定义中性类。该指标不能证明目标确认或防守成功。
- 继续攻击建议：`(t,t+H]` 内有本机“发弹”事件记对齐，无事件记中性；反向行为没有可定义证据，因此“不适用”而非0%。发弹不说明目标匹配或建议导致发弹。10s/30s为累计窗口，30s累计事件率天然更高。
- 95% CI 采用 1,000 次按整场比赛重采样的 cluster bootstrap，而非把重复帧当独立样本；表中列出每个分层实际贡献的比赛数。覆盖率是描述性点估计，响应率 CI 在各分层单独计算。

## 执行状态及后续改进

- JSON 每个分层都标记 `execution_status=unobservable`：没有控制器命令/确认日志，不存在真实执行率指标。若界面展示状态，应写“执行未观测；行为响应：接近目标区/未明显变化/远离目标区、留在原区/离开原区、观察到发弹”，同时显示时间窗。
- 对低血撤离，优先完善目标区边界距离、目标选择理由、速度/朝向、路线时间估计及取消条件。反向响应高时，应复核建议触发条件与功能区路线质量，不能用调阈值掩盖。
- 若要评估建议是否带来收益，需要指令目标与回执、取消/改派、目标可见性、威胁/战果和可比对照；现有数据无法作因果归因。
