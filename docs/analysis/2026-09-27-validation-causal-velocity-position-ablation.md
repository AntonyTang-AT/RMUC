# 因果质心速度位置解码消融（仅 validation）

日期：2026-09-27。比较冻结的 canonical-side GRU 位置输出、仅用因果速度外推、以及两者按不同权重线性融合。未读取 test，未更新生产默认。

## 速度与评估口径

- 输入只取 `out_m2/forecast_dataset/validation.jsonl.gz` 中的 issue-time `observable`，对每一行 `game_id / observing side / self-or-opponent / entity_type`，计算存活且有 XY 观测机器人的组质心。
- 速度为当前组质心减去同组精确 `issued_at - 3s` 组质心，再除以 3 秒。缺少前一观测时速度不可用，外推退化为当前位置。速度由当时传感器/雷达可见 XY 的因果差分估计，**不读取 yaw/车头朝向**，也不读取 target/future。
- 为抑制质心变化造成的异常跳跃，速度模长上限使用项目中按兵种设置的 `ROBOT_SPEED_MPS`。预测位置被截到场地 `[0,28]×[0,15]`。
- 真值用现有 `entity_y` 的未来 side+type 组均值位置。只评分未来存在且当前组可观测到位置的样本。主要指标是项目已有归一 L1 MAE：`mean((|dx|/28 + |dy|/15)/2)`，越低越好。区域命中率用预测/真值组均值坐标分别映射到功能区；因此对多台同兵种横跨多个功能区的情况，它不等同于“首台机器人区域”标签。
- 5-fold 按 `game_id` 分折；只在其余比赛上每个时距选出 MAE 最低的模型融合权重，再应用到留出比赛。对比赛做红蓝配对 bootstrap。权重指模型占比，`0` 是纯速度、`1` 是原模型。固定权重也同时列出，供审查趋势。

## 验证结果

| 预测时距 | 原模型 MAE | 纯速度 MAE | 交叉拟合所选权重（模型比例） | 交叉拟合 MAE | 区域命中：原模型 → 融合 |
|---:|---:|---:|---|---:|---:|
| 10 秒 | 0.14091 | 0.09038 | 0.25（五折一致） | 0.08658 | 23.84% → 44.39% |
| 30 秒 | 0.15228 | 0.18081 | 0.50、0.50、0.75、0.75、0.75 | 0.13935 | 22.27% → 26.83% |
| 60 秒 | 0.16100 | 0.24601 | 0.75（五折一致） | 0.15598 | 20.25% → 22.51% |
| 120 秒 | 0.16665 | 0.30668 | 1.00（五折一致） | 0.16665 | 19.06% → 19.06% |

所选融合相对原模型的 paired-game MAE 差（候选减原模型，2000 次 bootstrap）为：10s −0.05432，95% CI [−0.05645, −0.05210]；30s −0.01293 [−0.01438, −0.01157]；60s −0.00502 [−0.00591, −0.00410]；120s 0。区域命中变化分别为 +20.55、+4.55、+2.26、0 个百分点；相应 95% CI 为 [19.62,21.49]、[4.05,5.06]、[1.84,2.65]、[0,0] pp。所有归一 MAE 降幅的区间均不含 0。可评分预测中当前3秒速度可用比例约为 98.3–98.5%。

单独检查部署候选固定权重，不依赖每折独立选重：30 秒固定模型权重 0.75 得 MAE 0.13862、区域命中 25.94%（相对原模型 MAE 差 −0.01367，95% CI [−0.01442, −0.01285]；区域命中 +3.67pp，CI [+3.34,+4.01]）；60 秒固定权重 0.75 得 MAE 0.15598、命中 22.51%（MAE 差 −0.00502，CI [−0.00594, −0.00404]；命中 +2.26pp，CI [+1.85,+2.66]）。这确认 30/60 秒候选本身在验证折外有提升，而不只是权重搜索导致。

## 结论

这个可检验的简单解码改动有清晰的视距规律：10 秒模型占 25%、速度占 75%；30 秒模型占 75%、速度占 25%；60 秒同为 75/25；120 秒完全采用原模型。纯速度在 10 秒优于原模型，但 30 秒及更远显著更差。交叉拟合和固定 .75 权重结果都支持“短时速度约束、远时回归模型”的候选，但仍只是当前验证集上的选择结果，需在未触碰的新比赛/盲测上复现后才能考虑部署。

该消融只作用于 **side+兵种组质心**，不是单台机器人 track 的实测速度。组内机器人进出可移动质心；如果系统可持续维护同一 `entity_id` 的过去轨迹，下一步应比较 ID 匹配的实体速度、组质心速度和传感器直接速度。当前速度也没有融合底盘 heading，因为 observable 的 `yaw` 代表云台/炮口朝向，不能当作车头方向。

生产默认保持旧 decoder。运行时可通过 `resolve_temporal_forecaster(..., apply_validation_position_fusion=True)` 显式打开验证候选；回放演示可运行：

```powershell
python eval/build_battle_replay_visual.py --position-fusion-candidate --out C:/Users/AntonyTang/.codex/visualizations/rm-battle-replay-position-fusion.html
```

候选回放自身包含可见横幅和 JSON `forecast_configuration.position_fusion` 元数据。固定权重 0.75 的 30s/60s 结果是无验证时拟合步骤的固定配置评分，作为交叉拟合候选的单独检查；不能当作全新的盲测。

## 复现

在项目根目录运行：

```powershell
python eval/crossfit_validation_velocity_position.py --device auto --bootstrap 2000
```

机器、冻结检查点路径、validation NPZ/JSONL 哈希与完整分边逐折指标记录于 `out_m2/validation_velocity_position_ablation/report.json`。功能区分配用当前多边形按 5cm 网格快速栅格化，区域率是规划地图分辨率下的近似；连续 MAE 不使用栅格化。
